## MEM-UAT-001 开启记忆缺少用户设置入口

发现日期：2026-10-14。涉及入口：Desktop、TUI。状态：待修复。

### 用户反馈

用户在准备试用时提出：“真实用户使用的时候也是通过改 config 文件开启记忆的吗？”

### 当前行为

General Persistent Memory 默认关闭。用户首次开启时，需要找到 `DEVO_HOME/config.toml`，手动添加或修改以下配置，并重启 Devo 服务：

```toml
[memory]
enabled = true
```

Desktop 和 TUI 已有本轮记忆召回展示，但尚无可发现的记忆设置入口，用户无法直接在产品中开启全局记忆，或独立控制默认召回与后台学习。

会话级 `memoryRecall` / `memoryContribution` 设置不能覆盖关闭的全局 `memory.enabled` 门控。因此，已有会话设置接口不能替代首次开启入口。

### 用户影响

普通用户需要知道配置文件的位置、TOML 写法和服务重启方式，才能开始使用记忆。召回展示已经存在，但首次启用仍依赖产品外的手动操作。

### 复现步骤

1. 使用默认配置启动 Desktop 或 TUI。
2. 在产品的设置入口中寻找启用记忆、使用已有记忆和自动学习新记忆的控制项。
3. 确认目前需要通过编辑 `config.toml` 才能开启全局记忆。

### 期望与验收标准

- [ ] Desktop 设置页和 TUI 设置菜单或命令提供可发现的记忆设置入口。
- [ ] 用户无需手动编辑 TOML 即可开启或关闭全局记忆；默认仍为关闭，由用户主动开启。
- [ ] 用户可以独立控制使用已有记忆（召回）和后台学习新记忆（贡献）。
- [ ] 界面说明设置作用于全局还是当前会话，并正确表达全局关闭时会话设置不能启用记忆。
- [ ] 设置能够持久化，重启后显示与实际行为一致；需要重启的操作明确提示用户。
- [ ] 设置的生效时机与现有规则一致：召回设置影响下一轮，贡献设置影响下一次来源检查。
